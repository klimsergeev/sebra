# Рутина «Разбор»

Каждый час разбирает большие документы, которые приём отложил в фон (записи со `status: processing`): поручает их агенту `seb-digester`. Нечего разбирать — одна строка журнала в день и выход.

## Поля формы

Форма — https://claude.ai/code/routines → **New routine**. Все поля — одним сообщением, как их показывает `engine/SETUP.md`, шаг 6.

| Поле формы | Что ввести |
|------------|------------|
| Имя рутины | `sebra digester` |
| **Instructions** (текст рутины) | Текст из блока ниже, целиком |
| Модель (выбор модели в поле **Instructions**) | самая новая Sonnet в списке (6 октября 2026 — Sonnet 5.5) |
| **Select repositories** | `<владелец>/<база>` — репозиторий этой базы, только он |
| Настройки облака (**Select an environment**) | Те же, в которых вы открываете сессии базы, — **Claude Env** или **Default**, что есть в списке; в них **Network access** — **Full**. Новые не создавайте |
| **Select a trigger** | **Schedule**, каждый час (hourly) |
| **Connectors** | Убрать все |

```text
Выполни рутину разбора базы Sebra по файлу engine/routines/digester.md, раздел «Шаги», по порядку. Сохраняй только командой python3 engine/scripts/commit.py — она отправляет в main. Свою ветку claude/… не отправляй, git push не запускай.
```

Затем **Create** и на странице рутины — **Run now**.

## Шаги

Пользователя в рутине нет: вопросов не задавай. Ты — основная сессия рутины: сама данные не пишешь, только поручаешь агенту и вызываешь команды из шагов. Поручение — инструментом Agent, `subagent_type` — имя агента, без параметра `model`, текст строго по шаблону (ЗАДАЧА — из шага, СЕЙЧАС — вывод шага 1, остальное — «нет»):

```text
ЗАДАЧА: <строка из шага>
СЕЙЧАС: <вывод python3 engine/scripts/collect.py now>
МАТЕРИАЛ: нет
ВЛОЖЕНИЯ: нет
СЛОВА ПОЛЬЗОВАТЕЛЯ: нет
РЕШЕНИЯ: нет
ВЕРНИ: блок «Отчёт агента».
```

Сбой шага (команда вернула не 0, агент вернул ИТОГ «не сделано» или «нужно решение», отчёта нет) не останавливает рутину: запиши причину `python3 engine/scripts/journal.py add --who digester --action "сбой" --target engine/routines/digester.md --note "<шаг>: <причина или вопрос агента>"` и `python3 engine/scripts/commit.py --who digester --message "сбой"`.

1. `mkdir -p /tmp/sebra`; `python3 engine/scripts/collect.py now` (сегодняшняя дата — для журнала); найди записи со `status: processing`: `grep -l "^status: processing" data/records/*.md` (папки нет или код 1 — записей нет).
2. Записей нет: `grep -c " · seb-digester · нечего разбирать · " data/log/<сегодня>.md` — ноль или файла нет, то `python3 engine/scripts/journal.py add --who seb-digester --action "нечего разбирать" --target data/records` и `python3 engine/scripts/commit.py --who digester --message "нечего разбирать"` (без путей: журнал добавляется сам); строка уже есть — ничего не пиши. Выход. Так пустые запуски дают не больше одного коммита в день, а не 24.
3. Записи есть — поручи `seb-digester`, ЗАДАЧА «Разобрать большие документы». Свои правки агент сохраняет сам.

Последнее сообщение рутины — одной строкой, без путей, имён файлов и номеров коммитов (правило 10 в `CLAUDE.md`): ДЛЯ ПОЛЬЗОВАТЕЛЯ `seb-digester` из шага 3; записей нет (шаг 2) — «Разбирать нечего»; отчёта нет — «Разбор не отработал: <причина простыми словами>».
