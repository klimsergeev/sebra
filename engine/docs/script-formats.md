# Форматы файлов, которые пишут только скрипты движка

Агенты эти файлы не пишут и не читают. Форматы файлов, с которыми работают агенты, — `engine/docs/formats.md`; его общие правила о кодировке и датах действуют и для этих файлов. Проверяет их `python3 engine/scripts/lint.py`; чего он не проверяет — последний раздел.

## Подробный лог — `data/log/trace/<ГГГГ-ММ-ДД>-<session_id>.jsonl`

Шаги ходов с отметками времени — для разработчика: на каких шагах Sebra работает медленно. Писать ли — `trace.enabled` (раздел «Настройки»). Папка лежит внутри `data/log/`, но журналом не является: строк журнала в ней нет.

- Файл — JSON Lines: UTF-8, LF, одна строка — одно событие, объект JSON. Шапки нет. Порядок строк — порядок дописывания, а не время.
- Имя: день — день переноса в базу по поясу пользователя; `session_id` — `[A-Za-z0-9_-]{1,128}`, без сессии — `nosession`. Один файл на сессию и день.
- В событиях нет текстов пользователя, аргументов команд, имён его файлов, текстов поручений агентам, адресов и шаблонов поиска: метки шагов собираются только из слов движка и системы (ниже).

```json
{"t": 1761553331.123, "ev": "post", "sid": "<session_id>", "pid": "<prompt_id>", "agent": "seb-intake", "aid": "<agent_id>", "effort": "low", "tid": "<tool_use_id>", "tool": "Bash", "what": "commit.py", "ms": 2140, "x": {}}
```

Образец собирает все поля в одну строку. В настоящей строке есть `t`, `ev`, `sid`; остальные поля — только у видов, к которым они относятся (у `post` нет `what`), и только со значением: поля без значения в строке нет вовсе, пустого `x` не бывает. Пустым бывает только `agent` у `sub_start` и `sub_stop`.

| Поле | Значение |
|------|----------|
| `t` | Время события — секунды Unix с миллисекундами; у `hook` и `script` — конец работы хука или скрипта |
| `ev` | Вид события (таблица ниже) |
| `sid` | Сессия: `session_id` входа хука, у скриптов — `CLAUDE_CODE_SESSION_ID`; нет или не вида `[A-Za-z0-9_-]{1,128}` — `nosession` |
| `pid` | `prompt_id` хода — если Claude Code передал его во входе хука: у событий хуков лога, у `hook` и `session`; у `script` его нет |
| `agent` | Агент — только у событий хуков лога (у `session`, `hook`, `script` его нет): `agent_type` входа хука (`seb-intake`), если `.claude/agents/<agent_type>.md` есть в наборе движка (ниже), иначе `?` — так у встроенных агентов Claude Code и агентов плагинов; поля `agent_type` нет или оно пустое — `main`, основная сессия; у `sub_start` и `sub_stop` пустой `agent_type` остаётся пустым — внутренние агенты Claude Code |
| `aid` | `agent_id` субагента — у событий внутри субагента и у `sub_start`, `sub_stop` |
| `effort` | Уровень effort — `effort.level` входа хука: `low`, `medium`, `high`, `xhigh` или `max`, другое значение — `?`; объекта `effort` или его `level` во входе нет — поля нет. Только у событий хуков лога; Claude Code передаёт уровень у вызовов инструментов, `stop` и `sub_stop`, на моделях с уровнем effort; у вызова внутри субагента — уровень субагента. Уровень агента в отчёте — по событиям `pre` его вызовов |
| `tid`, `tool` | `tool_use_id` и имя инструмента — у `pre`, `post`, `fail` |
| `what` | Метка шага, имя хука движка или метка скрипта (ниже) |
| `ms` | Длительность, миллисекунды; у `hook` и `script` — целое, есть всегда |
| `x` | Подробности вида — объект |

| `ev` | Когда | Что в `what`, `ms`, `x` |
|------|-------|-------------------------|
| `session` | Начало сессии: новой, возобновлённой, после `/clear` и после сжатия контекста | `x`: `source` — `startup`, `resume`, `clear` или `compact`, другое — `?`; `version` — версия движка `X.Y.Z`, не прочитать — `?`; `remote` — облачная ли сессия |
| `prompt` | Сообщение, начинающее ход, или уведомление о завершении агента — оно тоже начинает ход | `x`: `routine` — ход рутины (сообщение начинается с «Выполни рутину »), `notify` — уведомление о завершении агента (`prompt` начинается с `<agent-message from="`), `chars` — длина сообщения |
| `pre` | Перед вызовом любого инструмента | `what` — метка шага |
| `post`, `fail` | Вызов инструмента закончен, успешно или с ошибкой | `ms` — время работы инструмента; у Agent в `x` — те из `totalDurationMs`, `totalToolUseCount`, `totalTokens`, `resolvedModel`, `status`, что есть в ответе инструмента; у `fail` в `x` — `is_interrupt` и `exit` — строка `Exit code N`, только если первая строка ошибки ровно такая; другого текста ошибки нет |
| `sub_start`, `sub_stop` | Субагент запущен, закончил | `agent` — тип субагента, если это агент движка, иначе `?`; у внутренних агентов Claude Code пустой; `aid` |
| `stop`, `stop_fail` | Ход закончен, оборван ошибкой | — |
| `compact` | Сжатие контекста: начало и конец | `x`: `phase` — `pre` перед сжатием, `post` после |
| `hook` | Отработал хук движка: `session_start.py`, `deliver.py hook-prompt`, `guard.py`, `deliver.py hook-stop` | `what` — имя хука, `ms` — его длительность, `t` — конец работы; `pid` — если он есть во входе хука; у `guard.py` в `x` — `deny`, если запретил |
| `script` | Отработал скрипт движка | `what` — метка скрипта, `ms` — длительность, `t` — конец работы, `x`: `code` — код выхода |

Метки собираются только из слов, которые задаёт движок или система, — у всех инструментов без исключений; что не опознано по правилам ниже, — `?`. Имена навыков, типы агентов (у Agent и в поле `agent`, в том числе у `sub_start` и `sub_stop`) и пути файлов движка сверяются с набором движка — списком `files` из `engine.lock` (раздел «Версия движка»): в лог попадает только то, что в этом списке есть, а слово, которое лишь похоже на имя, — нет. `engine.lock` нет или он не читается — эти метки `?`. Набор берётся из `engine.lock` при записи события: после обновления движка метки — по новой версии.
- Метка скрипта — имя скрипта движка из закрытого списка скриптов, который ведёт `trace_log.py` (`commit.py`), и подкоманда, если она есть в списке подкоманд этого скрипта (`collect.py now`, `config.py set`); других аргументов нет. Скрипта нет в списке — `?`, подкоманды нет в списке — метка из одного имени.
- Bash — строка делится на простые команды по `;`, `&&`, `||`, `|`, `|&`, `&`, скобкам и переводам строки; их метки — через «; », не больше 8, дальше «; …». Метка простой команды — по первому слову после присваиваний `ИМЯ=значение`: `python3 <…>engine/scripts/<имя>.py …` или сам такой путь первым словом — метка скрипта; другой запуск Python (`python3 -c …`) — `python3`; `git` — `git <подкоманда>`, если подкоманда из списка, иначе `git`; встроенная команда или ключевое слово оболочки из списка (`cd`, `echo`, `if`) или программа, найденная в системе по имени без `/`, — это имя; иначе `?`. Простая команда со встроенным документом `<<` получает метку, как любая другая, по первому слову, и на ней разбор кончается: ни тело документа, ни команды после неё в метку не идут (`cat <<'EOF' > f` и дальше что угодно — `cat`). Строка, которую не разобрать (незакрытая кавычка), — `?`.
- Skill — имя навыка, если `.claude/skills/<имя>/SKILL.md` есть в наборе движка; иначе или имени нет — `?`: навыки плагинов (`плагин:навык`) и встроенные навыки Claude Code — тоже `?`.
- Agent — только `subagent_type`, если `.claude/agents/<тип>.md` есть в наборе движка; иначе или поля нет — `?`: встроенные агенты Claude Code (`general-purpose`, `Explore`, `Plan`) и агенты плагинов — тоже `?`. Текст поручения не читается.
- Read, Write, Edit (`file_path`), Grep, Glob (`path`) — класс пути, поля нет — `?`: `tmp` (`/tmp/sebra/`), `вложение` (`/root/.claude/uploads/`); внутри базы — путь от корня базы без `.` и `..` (путь не от `/` — от корня): файл движка — этот путь, если он есть в наборе движка или это папка, в которой лежит хотя бы один файл набора (`engine/docs`, `.claude`; сам корень — `.`); путь в `CLAUDE.md`, `README.md`, `.claude/…`, `engine/…`, которого в наборе нет, — `?`; файл данных — самая длинная подходящая папка из списка `data/records`, `data/tasks`, `data/reminders`, `data/log/trace`, `data/log`, `data/wiki/topics`, `data/wiki/people`, `data/wiki/projects`, `data/wiki/sources`, `data/wiki`, `data/reports/daily`, `data/reports/weekly`, `data/reports`, иначе `data`; остальное — `другое`. Шаблонов поиска нет.
- Остальные инструменты — имя инструмента, без адресов и других параметров.

Кто пишет:
- Хуки лога и отметки хуков и скриптов движка дописывают события в рабочий файл сессии `/tmp/sebra/trace/<session_id>.jsonl` вне базы — только при включённом логе.
- В базу события переносит только `commit.py` — при каждом сохранении, кроме `--who engine`. Он дописывает строки рабочих файлов в конец файла дня и обнуляет рабочий файл; новые и изменённые файлы лога уходят в коммит этого сохранения. Строки, записанные до выключения лога, тоже переносятся.
- Тот же перенос удаляет файлы, день в имени которых старше 30 дней, и удаление уходит в тот же коммит.
- Агенты в `data/log/` не пишут: папка им закрыта. Строки после переноса не меняются.
- `lint.py` проверяет только имена файлов и то, что в папке нет вложенных папок.

## Настройки — `config.yaml` и `engine/config.default.yaml`

Ключ стоит в разделе — строка раздела, под ней ключи с отступом в два пробела — или без раздела, с первой позиции; значение — строка в двойных кавычках, целое или `yes`/`no` без кавычек; комментарий у ключа на той же строке. `config.yaml` повторяет `engine/config.default.yaml` строка в строку, отличаются только значения; ключ — один раз.

```yaml
# Настройки Sebra. Меняются только командой: python3 engine/scripts/config.py set <ключ> <значение>

owner:
  timezone: "UTC"              # часовой пояс пользователя, имя зоны вида Europe/Moscow

git:
  author_name: ""              # пусто — автор изменений Claude
  author_email: ""             # оба поля пустые или оба заполнены

gardener:
  time: "04:07"                # время рутины садовника; то же — в форме рутины

summary:
  time: "09:07"                # время рутины сводки; то же — в форме рутины

weekly:
  day: "sunday"                # день недельного обзора и слияния правил

tasks:
  stuck_after_days: 14         # задача без изменений дольше — без движения
  delete_after_days: 30        # сделанная или отменённая задача удаляется через столько дней

big_docs:
  text_words: 8000             # md, txt, страница, письмо, eml, rtf, epub, прочий текст
  pdf_pages: 20                # PDF с текстом
  scan_pages: 5                # PDF-скан, фото документа
  doc_pages: 20                # docx, odt, doc; страница — из свойств файла, иначе 400 слов
  slides: 20                   # pptx, odp
  table_rows: 5000             # csv, tsv
  sheet_cells: 5000            # xlsx, ods — заполненные ячейки
  sheets: 5                    # xlsx, ods — листов

language:
  main: "ru"
  translate_quotes: yes        # цитата не на русском — рядом перевод

answers:
  quotes: yes                  # дословные цитаты в ответах: yes — показывать, no — не показывать

# Модели агентов: opus, sonnet, haiku или fable. Значение переносится в поле model файла агента.
agents:
  intake: "opus"               # модель приёма присланного
  answer: "opus"               # модель ответов на вопросы по базе
  digester: "opus"             # модель разбора больших документов
  gardener: "opus"             # модель садовника
  reporter: "sonnet"           # модель сводок и недельного обзора
  rules: "opus"                # модель правил из поправок
  challenger: "fable"          # модель спорщика
  restorer: "sonnet"           # модель отката и удаления

# Уровни обдумывания агентов: low, medium, high, xhigh или max. Значение переносится в поле effort файла агента.
intake-effort: "low"           # уровень приёма присланного
answer-effort: "low"           # уровень ответов на вопросы по базе
digester-effort: "medium"      # уровень разбора больших документов
gardener-effort: "medium"      # уровень садовника
reporter-effort: "medium"      # уровень сводок и недельного обзора
rules-effort: "medium"         # уровень правил из поправок
challenger-effort: "medium"    # уровень спорщика
restorer-effort: "medium"      # уровень отката и удаления

trace:
  enabled: yes                 # подробный лог шагов для разработчика: yes — писать, no — не писать
```

| Ключ | Допустимо |
|------|-----------|
| `owner.timezone` | Имя зоны, которое находит `zoneinfo.ZoneInfo` |
| `git.author_name`, `git.author_email` | Оба пустые или оба заполнены; почта содержит `@` |
| `gardener.time`, `summary.time` | `ЧЧ:ММ`, 00:00–23:59 |
| `weekly.day` | `monday` … `sunday` |
| `tasks.*`, `big_docs.*` | Целое от 1 до 100 000 |
| `language.main` | `ru` |
| `language.translate_quotes` | `yes` или `no`, без кавычек |
| `answers.quotes` | `yes` или `no`, без кавычек; только ответы пользователю: цитаты в файлах базы пишутся всегда |
| `agents.*` | `opus`, `sonnet`, `haiku`, `fable` — алиасы поля `model` агента Claude Code (https://code.claude.com/docs/en/sub-agents, раздел «Choose a model»); полное имя модели (`claude-opus-5-5`) и `inherit` поле тоже принимает, настройка — нет: алиас сам переходит на новую версию модели, а опечатку в полном имени проверка без сети не поймает; `inherit` отдал бы выбор модели основной сессии |
| `intake-effort`, `answer-effort`, `digester-effort`, `gardener-effort`, `reporter-effort`, `rules-effort`, `challenger-effort`, `restorer-effort` | `low`, `medium`, `high`, `xhigh`, `max` — значения поля `effort` агента Claude Code (https://code.claude.com/docs/en/sub-agents, таблица полей файла агента); с моделью агента уровень не сверяется: неподдержанный уровень Claude Code сам заменяет высшим поддержанным не выше заданного |
| `trace.enabled` | `yes` или `no`, без кавычек; `no` — хуки и скрипты движка не пишут новых событий, уже записанные переносятся и хранятся как обычно |

`engine/config.migrations.yaml` — список `- version: "X.Y.Z"` с `rename: {старое: новое}` и `remove: [ключ]` (`python3 engine/scripts/config.py`); пока переименований и удалений не было — строка-комментарий о назначении файла и `[]`.

## Версия движка — `engine.lock`

```yaml
version: "0.1.0"
source: "https://github.com/klimsergeev/sebra.git"
commit: "<40 знаков sha коммита версии>"
installed: "2026-10-06T10:15"
stashed_config: {}
files:
  - CLAUDE.md
  - engine/scripts/lint.py
```

Поля — ровно эти, каждое один раз: `version` — `X.Y.Z`; `source` — непустой адрес репозитория движка; `commit` — 40 знаков `0-9a-f`; `installed` — дата со временем; `stashed_config` — словарь (пустой — `{}`); `files` — непустой список путей от корня базы: файлы движка, каждый есть на диске; путей `data/`, `config.yaml`, `views.yaml`, `rules.local.md`, `engine.lock` в нём нет. Пишет только `update_engine.py`. Содержимое файлов движка — как в версии `commit`, кроме значений строк `model:` и `effort:` в шапках `.claude/agents/seb-*.md`: их пишет `config.py` из `agents.*` и `<имя>-effort` `config.yaml` (раздел «Настройки»).

## Сообщения коммитов

`<исполнитель>: <что>`: `seb-intake: data/records/…`, `seb-gardener: слито 2 страницы`, `summary: 2026-10-06`, `setup: база настроена`, `engine: version 0.2.0`. Автор и подписи — `commit.py`; проверяют скрипты движка, не `lint.py`.

## Что `lint.py` не проверяет

Остальное в этом файле и в `formats.md` проверяет `lint.py`; эти требования — нет, их соблюдают агенты:
- пересказ помечен словом «Пересказ:»; текст — по-русски; язык цитаты определяется только по буквам (правило перевода — раздел «Общие правила» `formats.md`);
- даты — по поясу пользователя; дата факта — когда он стал известен; `area` — по смыслу; `slug` датированных файлов — по смыслу; `slug` страниц тем, людей и проектов — транслитерацией названия; дата в имени файла напоминаний, журнала и подробного лога — день напоминания, день строк и день переноса;
- тело записи — дословный текст присланного; `type` записи — по виду материала, `why` — слова пользователя; `error` «цитаты не дословные: …» у записи, текст которой взят через WebFetch; запись создана на всё, что стоило сохранить; `record: ""` у задачи — только после удаления записи; дата факта равна `captured` его записи; ссылки в теле записи и в `rules.local.md`;
- пункт «Противоречия» — на каждой странице, где стоит один из фактов, и его дата — когда противоречие замечено;
- что перечислено в разделах «Что сделал садовник», «Большие документы» и в разделах обзора и в каком порядке (проверяются разделы, строки «Нет» и пустого дня, «Обновления», ссылки по форме и ссылки на задачи в «Делах на день»); в новой сводке — смысл вида: какие задачи подходят группам с `about` и категориям `split`, какие напоминания — группам напоминаний; порядок задач и напоминаний внутри группы и категории (основной вид — по сроку, запасной вид по умолчанию — по пути задачи); сохранённая сводка по виду (только по форме: вид мог смениться после неё); слова действия в журнале у всех, кроме `seb-gardener`;
- номера коммитов и имена скриптов без `.py` в тексте сводки и обзора;
- содержимое файлов движка — как в версии `commit` (сверяет `update_engine.py` при установке);
- смысл строки правила («<что> <когда>») и пояснений в «Связанном», оглавлении, журнале;
