# Форматы файлов базы Sebra

Форматы всех файлов, которые агенты и скрипты пишут в базу. Проверяет их `python3 engine/scripts/lint.py`; чего он не проверяет — раздел «Что `lint.py` не проверяет». Файла или поля без формата нет.

## Общие правила

- UTF-8 без метки порядка байтов, переводы строк LF, Markdown. Шапка — YAML между первой строкой `---` и следующей строкой `---`.
- Даты — `"ГГГГ-ММ-ДД"`, дата со временем — `"ГГГГ-ММ-ДДTЧЧ:ММ"`, в двойных кавычках, настоящие (не `2026-02-30`, не `24:00`), по поясу пользователя.
- Поля шапки — ровно перечисленные в формате файла, каждое один раз. Текст и пути — в двойных кавычках, одной строкой; внутри — кавычки-ёлочки, прямой кавычки `"` нет, обратная косая черта удваивается. Пустое значение — только `""`: не `null`, не `~`, не пустое место после двоеточия. Значения из закрытого списка и `true`/`false` — без кавычек.
- Пути в шапке — от корня базы, без `./`, `../` и `/` в начале, к существующему файлу в папке, которую называет формат поля.
- Ссылки в тексте — `[текст](путь.md)` относительно файла, на файл `.md` внутри `data/`; без пробелов, скобок и угловых скобок в пути; якорь после `#` допустим и не проверяется; определений ссылок вида `[метка]: путь` нет. Внешние адреса (`http://`, `https://`) и ссылки в блоках кода, в строчном коде и в строках цитат `>` не проверяются.
- Язык — русский. Цитата — дословно, на языке оригинала, одной строкой `> «…»`. При `language.translate_quotes: yes` цитата, в которой есть буквы и нет ни одной кириллической, считается не русской: сразу следующей строкой — `> Перевод: «…»`.
- Пересказ всегда помечен словом «Пересказ:».

## Имена файлов

| Папка | Имя |
|-------|-----|
| `data/records/` | `<ГГГГ-ММ-ДД>-<ЧЧММ>-<slug>.md` |
| `data/wiki/topics/`, `people/`, `projects/` | `<slug>.md` |
| `data/wiki/sources/`, `data/tasks/` | `<ГГГГ-ММ-ДД>-<slug>.md` |
| `data/reminders/`, `data/reports/daily/`, `data/reports/weekly/`, `data/log/` | `<ГГГГ-ММ-ДД>.md` |

- `slug` — `[a-z0-9]+(?:-[a-z0-9]+){0,5}`, от одного до шести слов. Имя занято другим файлом — к `slug` добавляется `-2`, `-3`, … (седьмым словом, если слов уже шесть): шаблон с номером — `[a-z0-9]+(?:-[a-z0-9]+){0,5}(?:-[1-9][0-9]*)?`. Имя сверяется целиком.
- Дата и время в имени совпадают с шапкой: у записи — `captured` (`"2026-10-06T09:14"` → `2026-10-06-0914-…`); у конспекта и задачи — `created`; у ежедневной сводки — `date`; у недельного обзора — `week_to`. У напоминаний — день напоминания, у журнала — день его строк.
- `slug` страниц тем, людей и проектов делает только `collect.py slug` — транслитерацией: а-a, б-b, в-v, г-g, д-d, е-e, ё-e, ж-zh, з-z, и-i, й-i, к-k, л-l, м-m, н-n, о-o, п-p, р-r, с-s, т-t, у-u, ф-f, х-kh, ц-ts, ч-ch, ш-sh, щ-shch, ъ-ie, ы-y, ь — пропуск, э-e, ю-iu, я-ia; знаки и пробелы — дефис. У датированных файлов `slug` — латиницей по смыслу.

## Запись — `data/records/`

```yaml
---
type: link
captured: "2026-10-06T09:14"
title: "Схема оплаты в новом сервисе"
pointer: "https://example.com/article"
why: "для доклада в пятницу"
status: done
seen: ["2026-10-08"]
size: "1200 слов"
error: ""
---
```

| Поле | Значение |
|------|----------|
| `type` | `text` — текст сообщения, мысль, сведение, слова пользователя из разговора; `link` — страница по ссылке (в том числе PDF по ссылке); `message` — письмо, вставленное текстом или файлом `eml`; `image` — картинка или фото, в том числе фото документа; `document` — файл `pdf`, `docx`, `odt`, `doc`, `rtf`, `epub`, `pptx`, `odp`, `xlsx`, `ods`, `csv`, `tsv`; `file` — `md`, `txt`, прочий текст и тип не из таблицы «Типы файлов»; `audio`, `video` — аудио и видео. Архив записью не становится: запись — на каждый файл из него, `type` — по типу файла |
| `captured` | Дата со временем получения |
| `title` | Непустой текст |
| `pointer` | У `text` и у письма, вставленного текстом, — `""`; у `link` — адрес `http://` или `https://`; у вложения — `"вложение от ГГГГ-ММ-ДД: <исходное имя файла>"`; у вложения без имени файла (картинка, вставленная в сообщение) — `"вложение от ГГГГ-ММ-ДД: картинка из сообщения"`; у файла из архива — `"вложение от ГГГГ-ММ-ДД: <имя архива>/<путь внутри архива>"`; у вложения письма `eml` — `"вложение от ГГГГ-ММ-ДД: <имя файла eml>/<имя вложения>"` (вложение письма из архива — `<имя архива>/<путь письма>/<имя вложения>`). Пустого `pointer` у вложения нет. Путей `/root/…` и `/tmp/…` нет: они исчезают после сессии |
| `why` | Слова пользователя рядом с материалом дословно; нет — `""` |
| `status` | `done` — разобрано; `processing` — большой документ ждёт разбора; `unreadable` — содержимое не читается. У `audio` и `video` — всегда `unreadable`. Меняется только с `processing` на `done` или `unreadable` |
| `seen` | Даты повторных присылок: список дат в двойных кавычках в квадратных скобках через запятую, по возрастанию, без повторов, не раньше даты `captured`; повторов не было — `[]`. Новая дата дописывается в конец |
| `size` | `"<целое> <единица>"` по мере из таблицы «Типы файлов» («12 страниц», «8500 слов», «14 слайдов»); меры нет — `""` |
| `error` | У `unreadable` — непустая причина; текст страницы взят через WebFetch — `"цитаты не дословные: <причина>"`; иначе — что не удалось или `""` |

Тело — дословно: текст сообщения; текст страницы; текст документа; текст письма целиком; у `image` — весь текст с картинки и строка, начинающаяся с «Что на картинке: »; у `processing` — тоже весь текст документа (разборщик читает его из записи: оригинала на машине рутины нет). Запись, созданная со `status: unreadable` (в том числе `audio`, `video`), — тело ровно одна строка «Содержимое не читается: <причина>»; запись, которую разборщик перевёл из `processing` в `unreadable`, сохраняет прежнее тело. После первого коммита записи тело не меняется; в шапке меняются только `status`, `seen`, `error`. Создаёт запись только `python3 engine/scripts/record.py new` (`python3 engine/scripts/record.py`): он ставит имя, шапку и тело и проверяет запись `lint.py`; правила для шапки после создания — те же и до первого коммита.

## Страницы знаний — `data/wiki/`

Общие поля:

```yaml
---
type: topic
title: "Платёжные системы"
area: work
created: "2026-10-06"
updated: "2026-10-06"
---
```

`type` — по папке: `topics/` — `topic`, `people/` — `person`, `projects/` — `project`, `sources/` — `source`. `title` — непустой текст. `area` — `work` или `personal`; неясно — `personal`. `updated` не раньше `created`.

| Тип | Дополнительные поля | Разделы по порядку |
|-----|--------------------|--------------------|
| `topic` | — | `## Кратко`, `## Факты`, `## Связанное`, `## Противоречия` |
| `person` | `role` — текст или `""` | `## Кратко`, `## Факты`, `## Связанное`, `## Противоречия` |
| `project` | `status` — `active`, `paused`, `done` | `## Кратко`, `## Факты`, `## Решения`, `## Задачи`, `## Связанное`, `## Противоречия` |
| `source` | `record` — путь к записи в `data/records/`; `author` — текст или `""`; `published` — `"ГГГГ"`, `"ГГГГ-ММ"`, `"ГГГГ-ММ-ДД"` или `""` | `## О чём`, `## Ключевые цитаты`, `## Что затронуто` |

- Разделы типа есть всегда, все, по порядку, каждый один раз; других заголовков `## ` нет. Пустой раздел — без строк.
- `## Кратко`, `## О чём` — свободный текст.
- `## Факты` и `## Решения` — пункты по формату «Факт».
- `## Связанное`, `## Задачи`, `## Что затронуто` — пункты `- [<название>](<путь>.md)`, после ссылки — необязательно ` — <пояснение>`. Цели: у «Связанного» и «Что затронуто» — страницы `data/wiki/`, у «Задач» — файлы `data/tasks/`.
- `## Ключевые цитаты` — строки цитат `> «…»` из тела записи из поля `record` (под не русской — строка перевода); между цитатами допустимы пустые строки.
- `## Противоречия` — пункты по формату «Противоречие».

**Факт** — пункт раздела `## Факты` или `## Решения`:

```markdown
- **2026-10-06** — Оплата в новом сервисе проходит в три шага.
  Источник: [Схема оплаты](../../records/2026-10-06-0914-skhema-oplaty.md)
  > «Payment is processed in three steps»
  > Перевод: «Оплата проходит в три шага»
```

- Строка пункта `- **ГГГГ-ММ-ДД** — <текст>` без отступа; остальные строки пункта — с отступом в два пробела. Между пунктами допустимы пустые строки; других строк без отступа в разделе нет.
- Ровно одна строка `Источник: [<название>](<путь>)` — ссылка на запись в `data/records/`.
- Хотя бы одна строка цитаты `> …` (строка `> Перевод: …` цитатой не считается). Каждая цитата после приведения — снять `>`, кавычки `«»“”„"'`, пробелы и переводы строк свести к одному пробелу — есть в теле записи из строки `Источник:`, приведённом так же.
- Перевод — сразу под цитатой, которую переводит.
- Дата — когда факт стал известен: дата `captured` записи из строки `Источник:`. При слиянии страниц и пересборке факта не меняется.
- Устаревший факт не удаляется: в конец строки пункта — « (устарело ГГГГ-ММ-ДД)».

**Противоречие** — пункт раздела `## Противоречия` на каждой странице, где стоит один из фактов:

```markdown
- **2026-10-08** — Срок подписания: 15 октября ([запись](../../records/2026-10-06-0914-ivan-dogovor.md)) или 20 октября ([письмо](../../records/2026-10-08-1102-ivan-perenos.md)).
  Текущее: 20 октября — ответ пользователя 2026-10-08
```

- Строка пункта `- **ГГГГ-ММ-ДД** — <обе версии>` без отступа, дата — когда противоречие замечено; в строке не меньше двух ссылок на записи в `data/records/`.
- Необязательная вторая строка с отступом в два пробела: `Текущее: <версия> — <причина>`; причина — ровно одно из: `ответ пользователя ГГГГ-ММ-ДД`, `по надёжности источника`, `по свежести`. Строки «Текущее» нет — противоречие не решено.

## Задача — `data/tasks/`

```yaml
---
type: task
title: "Позвонить Ивану про договор"
area: work
status: open
due: "2026-10-10"
project: "data/wiki/projects/dogovor.md"
record: "data/records/2026-10-06-0914-ivan-dogovor.md"
created: "2026-10-06"
updated: "2026-10-06"
closed: ""
---
```

- `title` — непустой текст; `area` — `work` или `personal`; `status` — `open`, `doing`, `waiting`, `done`, `dropped`; `due` — дата или `"none"`; `project` — путь к странице в `data/wiki/projects/` или `""`; `record` — путь к записи в `data/records/`; `""` — только у задачи, чья запись удалена по просьбе пользователя (`CLAUDE.md`, раздел «Общие правила»).
- `updated` не раньше `created`. `closed`: у `done` и `dropped` — дата закрытия, не раньше `created` и не позже `updated`; у остальных — `""`.
- Тело — `## Описание` (необязательно, свободный текст) и `## История` (обязательно, хотя бы одна строка): строки `- ГГГГ-ММ-ДД — <что изменилось>`.

## Напоминания на день — `data/reminders/<ГГГГ-ММ-ДД>.md`

```markdown
- Позвонить Ивану про договор — [запись](../records/2026-10-06-0914-ivan-dogovor.md)
```

Без шапки. Строка — `- <что напомнить> — [запись](../records/<имя записи>.md)`: текст непустой, запись есть в `data/records/`. Одна строка на напоминание, одинаковых строк нет, пустых строк нет. Пустого файла нет: опустевший удаляется. Пишет только `remind.py`; строки, которые пользователь увидел в сводке, он убирает по команде `deliver.py shown`.

## Ежедневная сводка — `data/reports/daily/<ГГГГ-ММ-ДД>.md`

```yaml
---
type: daily
date: "2026-10-06"
---
```

Тело — четыре раздела по порядку:
1. `## Напоминания` — сегодняшние, затем «за прошлый день»;
2. `## Дела на день` — подразделы `### Просрочено`, `### На сегодня`, `### Зависшие`, `### В работе`, `### Ждёт ответа`, все пять, по порядку; задача — ссылкой на файл `data/tasks/`;
3. `## Что сделал садовник` — слито, пересобрано из записей, исправлено, удалено, устарело, противоречия — в чью пользу; страница или задача — ссылкой с её названием, файла уже нет — названием без ссылки;
4. `## Большие документы` — разбираются, разобраны.

Пустой раздел или подраздел — одна строка «нет». Пустой день — вместо разделов одна строка «Дел нет, ничего не менялось, зависших задач нет». Повторный запуск рутины и запрос «что сегодня» дописывают в конец раздел `## Обновление ЧЧ:ММ`: изменившееся с прошлой версии, списком, без заголовков внутри; после первого «Обновления» идут только «Обновления», время не убывает. Ссылки в сводке проверяются только по форме, не по наличию цели: сводка — снимок дня, а задачи и страницы-дубли потом удаляются. Текст сводки пользователь видит в диалоге как есть, ссылки — их текстом: путей и имён файлов вне ссылок, номеров коммитов, имён скриптов в нём нет.

## Недельный обзор — `data/reports/weekly/<ГГГГ-ММ-ДД>.md`

```yaml
---
type: weekly
week_from: "2026-09-28"
week_to: "2026-10-04"
---
```

`week_to` — дата обзора, `week_from` — на 6 дней раньше. Разделы по порядку: `## Что пришло`, `## Что выросло`, `## Задачи`, `## Что сделал садовник`, `## Движок` (стоящая версия; новая, если вышла, — номер и раздел `CHANGELOG.md`). Пустой раздел — одна строка «нет». «Обновление ЧЧ:ММ», ссылки и текст без путей — как у ежедневной сводки.

## Журнал — `data/log/<ГГГГ-ММ-ДД>.md`

Без шапки. Строка — ровно один из двух видов:

```text
- ЧЧ:ММ · <исполнитель> · <что сделал> · <путь>[ · <пояснение>]
- ЧЧ:ММ · <исполнитель> · поправка · <текст поправки>
```

Регулярное выражение для `lint.py`: `^- (?:[01]\d|2[0-3]):[0-5]\d · (?:seb-[a-z0-9]+(?:-[a-z0-9]+)*|gardener|summary|digester|setup|engine) · (?:поправка · [^·\n]+|[^·\n]+? · [^\s·]+(?: · [^·\n]+)?)$`. Пустых строк нет. Путь в строке может вести на удалённый файл и не проверяется; у строки `summary · основная сессия` на месте пути — id облачной сессии (`cse_…` или `session_…`). У садовника пояснение — причина изменения. Порядок строк после слияния — порядок отправки, не время.

Примеры:

```markdown
- 09:14 · seb-intake · запись создана · data/records/2026-10-06-0914-skhema-oplaty.md
- 04:12 · seb-gardener · слито · data/wiki/people/ivan-petrov.md · дубль data/wiki/people/ivan.md — тот же человек
- 10:00 · seb-digester · нечего разбирать · data/records
- 11:40 · seb-rules · поправка · не ставить задачи из рекламных писем
```

Постоянные слова действия — по ним считает `collect.py`: `seb-gardener` — `слито`, `исправлено`, `пересобрано из записи`, `противоречие`, `привязано`, `устарело`; `seb-digester` — `разобрано`, `не читается`, `нечего разбирать`; `record.py` — `запись создана`; `delete.py` — `удалено`, `черновик убран`; `remind.py` — `напоминание`, `напоминание отменено`, `напоминания показаны` (прежние строки `напоминания отправлены` остаются в журналах как есть); `deliver.py` — `основная сессия`, `сводка показана`, `сводка отправлена в сессию`, `сводка не отправлена в сессию`; `commit.py` — `конфликт: правка не вошла`. Действия остальных агентов — свободным текстом.

## Оглавление — `data/index.md`

```markdown
# Оглавление

## Темы
- [Платёжные системы](wiki/topics/platezhnye-sistemy.md) — work — как устроены платежи

## Люди
## Проекты
## Источники (последние 30)
```

- Первая строка — `# Оглавление`; разделы `## Темы`, `## Люди`, `## Проекты`, `## Источники (последние 30)` — все, по порядку.
- Строка — `- [<название>](wiki/<папка>/<файл>.md) — <area страницы> — <одна фраза>`; папка — своего раздела (`topics`, `people`, `projects`, `sources`); каждая страница — не больше одного раза.
- Каждая страница `data/wiki/topics/`, `people/`, `projects/` — в оглавлении. В «Источниках» — ровно 30 конспектов с наибольшими именами файлов (имя начинается с даты), все — если их меньше 30.

## Настройки — `config.yaml` и `engine/config.default.yaml`

Два уровня: раздел и ключ; значение — строка в двойных кавычках, целое или `yes`/`no` без кавычек; комментарий у ключа на той же строке. `config.yaml` повторяет `engine/config.default.yaml` строка в строку, отличаются только значения; ключ — один раз.

```yaml
# Настройки Sebra. Меняются только командой: python3 engine/scripts/config.py set <ключ> <значение>

owner:
  timezone: "UTC"              # часовой пояс пользователя, имя зоны вида Europe/Moscow

git:
  author_name: ""              # пусто — автор изменений Claude
  author_email: ""             # оба поля пустые или оба заполнены

gardener:
  time: "04:07"                # время рутины садовника; то же — в форме рутины

summary:
  time: "09:07"                # время рутины сводки; то же — в форме рутины

weekly:
  day: "sunday"                # день недельного обзора и слияния правил

tasks:
  stuck_after_days: 14         # задача без движения дольше — зависшая
  delete_after_days: 30        # сделанная или отменённая задача удаляется через столько дней

big_docs:
  text_words: 8000             # md, txt, страница, письмо, eml, rtf, epub, прочий текст
  pdf_pages: 20                # PDF с текстом
  scan_pages: 5                # PDF-скан, фото документа
  doc_pages: 20                # docx, odt, doc; страница — из свойств файла, иначе 400 слов
  slides: 20                   # pptx, odp
  table_rows: 5000             # csv, tsv
  sheet_cells: 5000            # xlsx, ods — заполненные ячейки
  sheets: 5                    # xlsx, ods — листов

language:
  main: "ru"
  translate_quotes: yes        # цитата не на русском — рядом перевод

answers:
  quotes: yes                  # дословные цитаты в ответах: yes — показывать, no — не показывать

# Модели агентов: opus, sonnet, haiku или fable. Значение переносится в поле model файла агента.
agents:
  intake: "opus"               # модель приёма присланного
  answer: "opus"               # модель ответов на вопросы по базе
  digester: "opus"             # модель разбора больших документов
  gardener: "opus"             # модель садовника
  reporter: "sonnet"           # модель сводок и недельного обзора
  rules: "opus"                # модель правил из поправок
  challenger: "fable"          # модель спорщика
  restorer: "sonnet"           # модель отката и удаления
```

| Ключ | Допустимо |
|------|-----------|
| `owner.timezone` | Имя зоны, которое находит `zoneinfo.ZoneInfo` |
| `git.author_name`, `git.author_email` | Оба пустые или оба заполнены; почта содержит `@` |
| `gardener.time`, `summary.time` | `ЧЧ:ММ`, 00:00–23:59 |
| `weekly.day` | `monday` … `sunday` |
| `tasks.*`, `big_docs.*` | Целое от 1 до 100 000 |
| `language.main` | `ru` |
| `language.translate_quotes` | `yes` или `no`, без кавычек |
| `answers.quotes` | `yes` или `no`, без кавычек; только ответы пользователю: цитаты в файлах базы пишутся всегда |
| `agents.*` | `opus`, `sonnet`, `haiku`, `fable` — алиасы поля `model` агента Claude Code (https://code.claude.com/docs/en/sub-agents, раздел «Choose a model»); полное имя модели (`claude-opus-5-5`) и `inherit` поле тоже принимает, настройка — нет: алиас сам переходит на новую версию модели, а опечатку в полном имени проверка без сети не поймает; `inherit` отдал бы выбор модели основной сессии |

`engine/config.migrations.yaml` — список `- version: "X.Y.Z"` с `rename: {старое: новое}` и `remove: [ключ]` (`python3 engine/scripts/config.py`); пока переименований и удалений не было — строка-комментарий о назначении файла и `[]`.

## Типы файлов и большие документы

| Тип | Как читается | Мера | Порог «большой» (ключ) |
|-----|--------------|------|------------------------|
| `md`, `txt`, прочий текст (`json`, `xml`, `yaml`, `log`, код) | Как есть | Слова | `big_docs.text_words` |
| Страница по ссылке | `fetch_page.py`; нет текста — WebFetch, пометка «цитаты не дословные» | Слова | `big_docs.text_words` |
| Письмо текстом в сообщении | Как есть | Слова | `big_docs.text_words` |
| `eml` | `extract.py`: отправитель, дата, тема, текст; вложения — каждое по своему типу | Слова | `big_docs.text_words` |
| `rtf`, `epub` | `extract.py` | Слова | `big_docs.text_words` |
| PDF с текстом | `extract.py` (`pdftotext -layout`, страницы — `pdfinfo`) | Страницы | `big_docs.pdf_pages` |
| PDF-скан (`extract.py`: `scan: true`), фото документа | Распознавание страниц как картинок инструментом чтения, кусками до 20 страниц | Страницы | `big_docs.scan_pages` |
| `docx`, `odt`, `doc` | `extract.py`; `doc` — `antiword` | Страницы | `big_docs.doc_pages` |
| `pptx`, `odp` | `extract.py` — слайды и заметки | Слайды | `big_docs.slides` |
| `csv`, `tsv` | `extract.py` | Строки | `big_docs.table_rows` |
| `xlsx`, `ods` | `extract.py` — все листы | Ячейки и листы | `big_docs.sheet_cells`, `big_docs.sheets` |
| Архивы `zip`, `tar`, `tar.gz`, `tgz` | `extract.py` распаковывает в `/tmp/sebra/`; каждый файл — отдельным вложением по своему типу | — | По каждому файлу |
| Картинка `jpg`, `png`, `gif`, `webp` | Инструмент чтения | — | Никогда |
| Картинка `heic`, `heif` | `extract.py` переводит в `jpg`, дальше — как картинка | — | Никогда |
| Аудио, видео | Не читается | — | — |
| Другое | Читается как текст — правило текста; нет — не читается | — | — |

Не читается — запись со `status: unreadable`; ответ пользователю: этот формат прочитать нельзя; для аудио — «надиктуйте текстом прямо в чат».

## Правила пользователя — `rules.local.md`

```markdown
# Мои правила

## Кто я

## Правила
- 2026-10-12 — не делать задачи из рекламных писем
```

Первая строка — `# Мои правила`; разделы `## Кто я` (свободный текст) и `## Правила` — оба, по порядку. Строка правила — `- ГГГГ-ММ-ДД — делать <что> <когда>` или `- ГГГГ-ММ-ДД — не делать <что> <когда>`.

## Версия движка — `engine.lock`

```yaml
version: "0.1.0"
source: "https://github.com/klimsergeev/sebra.git"
commit: "<40 знаков sha коммита версии>"
installed: "2026-10-06T10:15"
stashed_config: {}
files:
  - CLAUDE.md
  - engine/scripts/lint.py
```

Поля — ровно эти, каждое один раз: `version` — `X.Y.Z`; `source` — непустой адрес репозитория движка (в базе — `https://…`, в тестах — путь к голому репозиторию); `commit` — 40 знаков `0-9a-f`; `installed` — дата со временем; `stashed_config` — словарь (пустой — `{}`); `files` — непустой список путей от корня базы: файлы движка, каждый есть на диске; путей `data/`, `config.yaml`, `rules.local.md`, `engine.lock` в нём нет. Пишет только `update_engine.py`. Содержимое файлов движка — как в версии `commit`, кроме значения строки `model:` в шапках `.claude/agents/seb-*.md`: его пишет `config.py` из `agents.*` `config.yaml` (раздел «Настройки»).

## Сообщения коммитов

`<исполнитель>: <что>`: `seb-intake: data/records/…`, `seb-gardener: слито 2 страницы`, `summary: 2026-10-06`, `setup: база настроена`, `engine: version 0.2.0`. Автор и подписи — `commit.py`; проверяют скрипты движка, не `lint.py`.

## Что `lint.py` не проверяет

Остальное в этом файле проверяет `lint.py`; эти требования — нет, их соблюдают агенты, а ловят живая проверка и ревью:
- пересказ помечен словом «Пересказ:»; текст — по-русски; язык цитаты определяется только по буквам (правило перевода выше);
- даты — по поясу пользователя; дата факта — когда он стал известен; `area` — по смыслу; `slug` датированных файлов — по смыслу; `slug` страниц тем, людей и проектов — транслитерацией названия; дата в имени файла напоминаний и журнала — день напоминания и день строк;
- тело записи — дословный текст присланного; `type` записи — по виду материала, `why` — слова пользователя; `error` «цитаты не дословные: …» у записи, текст которой взят через WebFetch; запись создана на всё, что стоило сохранить; `record: ""` у задачи — только после удаления записи; дата факта равна `captured` его записи; ссылки в теле записи и в `rules.local.md`;
- пункт «Противоречия» — на каждой странице, где стоит один из фактов, и его дата — когда противоречие замечено;
- что перечислено в разделах сводки и обзора и в каком порядке (проверяются разделы, «нет», «Обновления», ссылки по форме и ссылки на задачи в «Делах на день»); слова действия в журнале у всех, кроме `seb-gardener`;
- номера коммитов и имена скриптов без `.py` в тексте сводки и обзора;
- содержимое файлов движка — как в версии `commit` (сверяет `update_engine.py` при установке);
- смысл строки правила («<что> <когда>») и пояснений в «Связанном», оглавлении, журнале;
- сообщения коммитов (проверяют скрипты движка);
- таблица «Типы файлов»: как читать, мера и пороги (проверяют скрипты движка), ответ пользователю о нечитаемом формате;
- кто какой файл пишет («пишет только …») (проверяют скрипты движка).
