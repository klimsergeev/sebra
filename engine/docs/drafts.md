# Черновики — шаги 11 и 12 агента приёма

Шаги 11 и 12 продолжают шаги файла агента приёма `.claude/agents/seb-intake.md`: шаги 1–10 и разделы «Общее для всех агентов» и «Отчёт агента», на которые ссылаются шаги ниже, — там.

## Шаги

11. **Разобрать черновики** (задача «Разобрать черновики», МАТЕРИАЛ «нет»). Черновик — несохранённый файл данных, оставшийся от прерванной или повторённой работы агента. Копию уже сохранённого убираешь сам; черновик, в котором есть хоть что-то, чего в базе нет, не трогаешь — показываешь пользователю и спрашиваешь. Сомневаешься, есть ли новое, — спроси: лишний вопрос стоит одного ответа, а убранного из базы не вернуть.
    1. Вывод команды `delete.py drafts` из первого ответа — список `drafts`: `path`; `state` — `new` (файла в базе никогда не было), `changed` (изменён сохранённый файл), `deleted` (сохранённый файл удалён с диска); `same_as` — сохранённый файл с тем же содержимым байт в байт или `""`. Список пуст или в нём только `deleted` — ИТОГ «сделано», СОХРАНЕНИЕ «нечего сохранять», ДЛЯ ПОЛЬЗОВАТЕЛЯ пусто.
    2. Реши по каждому, прежде чем что-то менять:
       - `new` с непустым `same_as` — копия: убрать.
       - `new` с пустым `same_as` вне `data/reminders/` — Read черновика и найди сохранённый файл того же вида о том же: запись — `python3 engine/scripts/record.py duplicate <path> --json`, в `duplicates` — записи с тем же адресом или тем же текстом (путь, который сам есть в `drafts`, — не сохранённый файл, а другой черновик: пункт о двух черновиках ниже); задачу — по `title` в `data/tasks/`; страницу — по `title` в `data/wiki/`. Всё, что есть в черновике, есть в найденном файле — копия: убрать; разница только в служебном (время и `slug` в имени файла, `captured`, `created`, `updated`, `seen`, строки «Истории») не в счёт; черновик, который лишь часть сохранённого текста, — тоже копия. Иначе — спросить.
       - Два черновика об одном и том же, которого в базе нет, — второй — копия первого: убрать; о первом — спросить.
       - `changed` — `git diff HEAD -- <path>`: отличается только служебными полями — копия: убрать; иначе — спросить.
       - Черновик в `data/reminders/` — спросить.
       - `deleted` — не трогать: удаляют сохранённые файлы только откат и садовник.
    3. Убрать копию: `python3 engine/scripts/delete.py draft <path> --who seb-intake --reason "копия сохранённого: <путь сохранённого файла>" --json` (второй из двух одинаковых — `--reason "копия черновика <путь первого>"`). Затем `python3 engine/scripts/commit.py --who seb-intake --message "черновики-копии убраны" --json` без путей: путей убранных черновиков ему не передавай — у `new` файла нет ни на диске, ни в базе, и `commit.py` откажет, у `changed` файл равен сохранённой версии, сохранять нечего; строки журнала он унесёт сам.
    4. Есть черновики «спросить» — ИТОГ «нужно решение»; РЕШЕНИЕ НУЖНО — «Сохранить в базу или убрать?» (несколько черновиков — «Сохранить в базу или убрать? Можно ответить по номерам»); <пути этих черновиков через «; »>. В ДЛЯ ПОЛЬЗОВАТЕЛЯ — что убрал (одной строкой) и что в каждом таком черновике, нумерованным списком, если их несколько, словами, без путей:
       - запись — вид и название, дата из `captured`; у ссылки — адрес; у вложения — имя файла и размер; у записи с текстом сообщения или мысли пользователя (`type: text`, письмо текстом) — ещё её тело целиком, отдельным блоком кода `text` под пунктом: это его же слова, по ним он узнаёт черновик; блок — и при `answers.quotes: no`;
       - задача — название, срок, описание;
       - страница — название и новые факты своими словами;
       - правка сохранённого файла (`changed`) — какая страница или задача и что в ней изменилось бы, своими словами;
       - напоминание — о чём и на какой день.
       Пример: «Не дошло до базы:» и под ним «1. Задача „Позвонить Ивану“ на 10.10 — такой в базе нет. 2. Запись от 10.10 с вашим сообщением:» и блок с текстом сообщения.
    5. Нет черновиков «спросить» — ИТОГ «сделано»; ДЛЯ ПОЛЬЗОВАТЕЛЯ — одной строкой, что убрал: «Задача „Позвонить Ивану“ уже в базе, лишнюю копию убираю». Ничего не убирал — пусто.
12. **Черновики: решение пользователя по <пути>** (и «… повторно по <пути>») — в РЕШЕНИЯХ ответ пользователя на вопрос шага 11 или на повторный вопрос этого шага, пути — из ЗАДАЧИ. Без явного «сохранить» черновик в базу не попадает. Черновика из ЗАДАЧИ нет в выводе команды `delete.py drafts` из первого ответа — его не трогай.
    1. Пойми ответ по каждому черновику: «сохрани», «оставь», «да» — сохранить; «убери», «удали», «не нужно», «нет» — убрать; ответ по номерам — по номерам списка из шага 11 в том же порядке путей; один ответ без номеров — для всех. Неясно, что делать с черновиком, — его не трогай: в ЗАДАЧЕ нет слова «повторно» — ИТОГ «нужно решение», РЕШЕНИЕ НУЖНО — «Что всё-таки сделать с <что словами>: сохранить в базу или убрать?»; <пути неясных черновиков через «; »>; в ЗАДАЧЕ есть «повторно» — ИТОГ «сделано», черновик остаётся, в ДЛЯ ПОЛЬЗОВАТЕЛЯ строка «Тогда <что словами> не сохраняю. Это останется только в этом диалоге и исчезнет вместе с ним». Ясные ответы по остальным черновикам выполняй, как ниже.
    2. Убрать: `new` и `changed` — `python3 engine/scripts/delete.py draft <path> --who seb-intake --reason "убрать по ответу пользователя" --json`; напоминание — `python3 engine/scripts/remind.py cancel --who seb-intake --date <день файла> --record <путь записи из строки черновика> --json`, в сохранение — путь из `file`. Ссылку на убранный черновик в черновике, который сохраняешь, убери Edit.
    3. Сохранить: новая страница темы, человека или проекта — строка в оглавлении; новая задача проекта — пункт в «Задачах» проекта (шаг 6). Строка журнала на каждый сохраняемый черновик — `--journal "черновик сохранён · <путь>"` в сохранение подпункта 4. Нарушения формата покажет ответ сохранения (`invalid`): у записи исправляй только поля шапки `status`, `seen`, `error`, тело — никогда.
    4. Сохранение — по пункту «Сохранение» раздела «Общее для всех агентов» в `seb-intake.md`: в `<пути>` — пути сохраняемых и исправленных файлов и `file` из `remind.py cancel` (кроме `deleted: true` у файла напоминаний, которого в базе не было: его не передавай — `commit.py` откажет). Пути убранных черновиков тоже не передавай: у `new` файла нет ни на диске, ни в базе — `commit.py` откажет; у `changed` файл равен сохранённой версии — сохранять нечего. Только убирал — `python3 engine/scripts/commit.py --who seb-intake --message "черновики убраны по ответу пользователя" --json` без путей.
    ДЛЯ ПОЛЬЗОВАТЕЛЯ — одной строкой, по названиям, без путей: «В базе теперь задача „Позвонить Ивану“, а запись от 10.10 удалена».
